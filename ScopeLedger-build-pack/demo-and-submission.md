# Demo and submission

## Three-minute recorded demonstration
0:00–0:20: Show original scope (website + CSV export) and actual GitHub tasks. Explain agency/client roles.
0:20–0:45: Send a fresh client email requesting a dashboard. Show real inbox arrival and case creation.
0:45–1:10: Agent retrieves scope/tasks via MCP and cites evidence; it does not invent a final price.
1:10–1:40: Verified manager publishes two confirmed choices: additional fee or swap CSV export for dashboard.
1:40–2:05: Verified client selects swap on exact proposal version. Receipt says accepted pending synchronization.
2:05–2:35: Open GitHub independently: new dashboard task, export supersession; open newly published scope document.
2:35–3:00: Replay acceptance; no duplicate task. Show one prepared failure/recovery trace with real provider evidence, labeled as previously recorded if not live.

## Six-minute finalist version
Use the additional time for live failure injection: stop after one provider write, restart n8n, reconcile and finish without duplicate effects. Show partial status before recovery. Explain competitor overlap candidly and state prototype limits. Do not rely on a fragile live email arrival for every explanation; keep a separately labeled recorded end-to-end run as backup.

## Submission checklist (handbook requirements; confirm corrected deadline)
- Team name, both full names/emails/registered Discord usernames, one contact number.
- Project name, one-line pitch, buyer/problem, human decision and implementation stack.
- Live Alternate Clouds link; keep running through required judging period.
- GitHub repository accessible to judges or exported n8n workflow download.
- Accessible 2–3 minute video.
- One teammate's original LinkedIn post and other's reshare.
- Discord membership and Alternate Clouds deployment-status screenshots.
- Dedicated demo login if needed; no personal passwords or API keys.
- Third-party code/template credits; all links independently checked.
- Actual deadline/freeze time confirmed with organizers: the user reported a mistake in the printed handbook. Do not reuse the printed time as authoritative.

## LinkedIn restriction
The handbook says participants must write the LinkedIn content themselves; AI-written posts cause disqualification and grammar-only assistance is allowed. This pack deliberately contains no LinkedIn post draft. Team writes its own post and verifies compliance.

## Claims to avoid
Production-ready, legally binding signature, fraud-proof identity, guaranteed recovered revenue, exactly-once distributed writes, unique/no competitors, complete multi-tenant isolation or any passing test not actually executed.
